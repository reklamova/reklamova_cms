# Zakres zmian Reklamova CMS 0.8.0-rc3 względem RC2

Data zamrożenia zakresu: 2026-07-30

## Punkty odniesienia

- artefakt RC2: `pkg_core_0_8_0_rc2`,
- commit źródłowy RC2: `b73c63127101166e35259736bf7d1db67c45e78f`,
- HEAD przeanalizowany przed zmianą metadanych RC3:
  `6dcd0d03ea047171704fa264711d45d3131121f9`,
- branch: `feature/client-panel-information-architecture`.

Zmiany dodane po podpisaniu RC2 obejmują dokładnie cztery pliki funkcjonalne.
Pozostałe różnice to metadane wersji oraz dokumentacja walidacyjna.

## Zmiany funkcjonalne

### `app/core/Database/ConnectionFactory.php`

- połączenie PDO jest ponawiane jeden raz po krótkiej przerwie,
- ponowienie dotyczy wyłącznie przejściowych błędów sieciowych, DNS i kodu 2002,
- błędy konfiguracji i błędy trwałe nadal przerywają połączenie wyjątkiem.

Zmiana wpływa na połączenie z bazą. Nie zmienia schematu bazy, migracji,
poświadczeń ani formatu konfiguracji.

### `app/core/Http/Application.php`

- błędy PDO na froncie i w panelu są przechwytywane,
- użytkownik otrzymuje kontrolowany komunikat HTTP 503 bez stack trace,
- szczegóły błędu są zapisywane wyłącznie w prywatnym logu aplikacji,
- normalny routing, fallbacki modułów i hooki Privacy Center pozostają bez zmian.

Zmiana wpływa na obsługę awarii połączenia w routingu publicznym i panelu.
Wymaga regresji publicznych fallbacków i hooków Privacy Center.

### `app/modules/catalog/admin.php`

- formularz produktu korzysta z dedykowanego pionowego kontenera,
- sekcje `Podstawowe`, `Opis i zdjęcia`, `Parametry` oraz `Ustawienia SEO`
  nie są już traktowane jako kolumny siatki pól.

Zmiana wpływa wyłącznie na ekran dodawania i edycji produktu. Repozytorium,
zapis produktu, powielanie, statusy i dane produktu nie zostały zmienione.

### `public/assets/core/admin.css`

- sekcje formularza produktu mają pełną szerokość,
- usunięto podwójny odstęp między sekcjami,
- pola formularza nie wymuszają poziomego przepełnienia,
- końcowy breakpoint mobilny przywraca jedną kolumnę panelu po wszystkich
  warstwach stylów.

Zmiana wpływa na UI panelu, przede wszystkim edycję produktu i zachowanie
panelu na telefonie oraz tablecie.

## Macierz wpływu

| Obszar | Wpływ RC3 | Uwagi |
| --- | --- | --- |
| Połączenie z bazą | TAK | Retry błędów przejściowych i kontrolowany HTTP 503 |
| Routing/front | OGRANICZONY | Tylko obsługa `PDOException`; normalne trasy bez zmian |
| Katalog/produkty | TAK | Wyłącznie układ formularza produktu |
| UI panelu | TAK | Formularz produktu i końcowy breakpoint mobile |
| Privacy Center | NIE | Kod bez zmian; wymagana regresja hooków |
| System aktualizacji | NIE | Kod updatera bez zmian |
| Migracje | NIE | Brak nowych i zmienionych migracji względem RC2 |

## Warunek builda

Build RC3 należy zatrzymać, jeżeli porównanie z artefaktem RC2 wykaże inną
nieopisaną zmianę funkcjonalną albo paczka obejmie ścieżkę chronioną.
